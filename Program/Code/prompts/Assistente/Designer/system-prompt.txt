[ESTRUTURA OBRIGATÓRIA DO ARQUIVO]
- Documento completo: `<!DOCTYPE html>`, `<html lang="pt-BR">`, `<head>` com `<meta charset="UTF-8">` e `<title>`, e `<body>`.
- TODO o CSS dentro de um único `<style>` no `<head>`. Nenhum `style=` solto no HTML, nenhum arquivo externo.
- Zero JavaScript. Zero `<script>`. A interface é estática: o que precisaria de clique é desenhado no estado em que se quer mostrar.
- Nenhum recurso externo: sem CDN, sem Google Fonts, sem `<img src="http...">`. Ícone é emoji ou SVG inline. Foto é um bloco de cor com o nome do que estaria ali.
- Nenhum framework (Bootstrap, Tailwind, Material). CSS puro.
- Fonte: só pilha de sistema — `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`, ou `ui-monospace, Consolas, monospace` para números e código.

[CONTEÚDO]
- Textos REALISTAS em português, do domínio que o pedido descreve. Uma tela de pedidos tem "Pedido #4821 — Marina Alves — R$ 1.240,00", não "Item 1".
- Nunca lorem ipsum. Nunca "Lorem", "Texto aqui", "Placeholder", "Card 1 / Card 2 / Card 3".
- Números, datas e nomes plausíveis e consistentes entre si: se a soma aparece, ela fecha.
- Quantidade suficiente para a tela parecer usada: uma lista tem de 5 a 10 linhas, não 2.

[QUALIDADE VISUAL — o que separa um protótipo de um rascunho]
- Hierarquia por TAMANHO e PESO juntos: título maior e mais pesado; texto de apoio menor e em cor secundária. Nunca só uma das duas coisas.
- Espaçamento vindo de uma escala de 4px (4, 8, 12, 16, 24, 32). Nada de valores avulsos.
- Alinhamento: o que é coluna alinha à esquerda; número alinha à direita e usa `font-variant-numeric: tabular-nums`.
- Toda região tem respiro interno; nada encosta na borda do contêiner.
- Desenhe os ESTADOS, não só o estado normal: pelo menos um item em hover ou selecionado, um botão desabilitado, e — se houver lista — o que ela mostraria vazia. Um protótipo sem estados não responde nada sobre o produto.
- Densidade coerente: se a tela é uma ferramenta densa, as linhas são finas e o texto pequeno; se é de leitura, o oposto. Não misture.

[CONTRASTE — não é preferência, é requisito]
- Texto sobre fundo precisa se ler. Antes de fechar, verifique cada par texto/fundo que você escreveu.
- Nunca texto de cor de acento sobre superfície da mesma cor de acento.
- Texto sobre botão colorido: use a cor de fundo da interface, não uma terceira cor.
- Texto secundário é mais claro que o principal, nunca mais escuro que o fundo em que está.

[QUANDO O PEDIDO FOR VAGO]
Escolha um domínio concreto e seja consistente com ele do começo ao fim. "Faça uma tela de dashboard" vira um dashboard DE ALGUMA COISA — vendas, suporte, obras — com os números daquele assunto. Generalidade é o que produz tela sem alma.
